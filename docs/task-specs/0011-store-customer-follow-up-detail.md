## 2. 需求确认卡

### 2.1 业务目标

在现有门店客户列表中，通过行级“操作 → 跟进详情”打开一级右侧抽屉，让用户在不离开列表的情况下查看当前客户的跟进流程、到店记录、拜访记录、通话记录和分配记录。

### 2.2 修改范围

本阶段只允许完成：

1. 将现有“跟进详情”菜单项接入一级右侧抽屉。
2. 实现跟进详情抽屉的标题、关闭、独立滚动和 `70vw` 宽度。
3. 实现五个固定 Tab 及切换。
4. 实现跟进流程中的用户信息、跟进概览、跟进旅程。
5. 实现到店记录、拜访记录、通话记录、分配记录四个只读列表 Tab。
6. 使用稳定的纯前端 Mock 数据展示本阶段状态。
7. 增加本任务直接需要的 Story、测试和页面内样式。
8. 必要时复用 0010 Phase 1 已上线的基础组件，但不修改其既有行为。

### 2.3 明确不做

- 不实现到店记录二级抽屉。
- 不实现拜访记录二级抽屉。
- 不实现添加到店表单或添加拜访表单。
- 不实现通话记录详情或音频播放。
- 不实现分配记录详情。
- 不实现到店、拜访旅程卡片的“详情”行为。
- 不实现记录列表“操作”列中的详情、编辑或其他动作。
- 不实现数据持久化、LocalStorage、后端接口、数据库或真实服务。
- 不进入 0010 Phase 2，不提前抽取业务尚未稳定的通用组件。
- 不新增第二套“跟进详情”入口，不跳转路由，不创建新页面或 Modal。
- 不新增正式 Requirement 编号、key 或需求对象；如产品要求新增映射，必须先确认 `requirementNo`、`displayNumber` 和稳定 ID，再单独补充任务范围。

### 2.4 业务规则

- 抽屉绑定当前点击行的客户，底层门店客户列表始终保留。
- 用户身份字段必须来自当前列表选中的 `CustomerRecord`，不得复制第二套客户身份数据。
- 页面专用记录 Mock 可独立维护，但必须通过稳定客户 key 与当前客户关联。
- 五个 Tab 全部可切换，默认 Tab 固定为“跟进流程”。
- 四类记录只读展示；本阶段所有新增、详情和操作入口均只保留视觉。
- 空值统一展示 `--`，金额统一保留两位小数。
- 跟进旅程按时间倒序，最新记录在前。
- 跟进旅程列表底部使用现有后台风格分页（纯前端 Mock，默认 10 条/页，切换筛选后总数与分页状态同步）。

### 2.5 UI 等级

- UI 验收等级为 C 级。
- 现有系统风格、产品经理提供的参考和已验收门店客户页面共同构成视觉基准。
- 必须严格检查抽屉宽度、层级、留白、字号、行高、边框、颜色、Tab、表格密度和对齐。
- 不得把内容自由改造成 Dashboard，不得用彩色数据大屏卡片替代本任务结构。
- 如果缺少某项像素基准，先沿用当前页面设计语言和 Ant Design 现有 token，不凭空创造视觉体系。
- C 级真实页面验收由产品经理完成；代码测试和 Codex Review 不替代产品经理的视觉确认。

### 2.6 验收标准摘要

- 唯一入口可打开、关闭一级跟进详情抽屉，抽屉宽度为 `70vw`。

- 五个 Tab 均可切换，默认展示跟进流程。
- 跟进流程的三段结构、用户信息、四张概览卡和旅程空/有数据状态正确。
- 四类记录表格字段数量、名称、顺序和共同展示规则正确。
- 当前 52 列、审批、Requirement 13、新办成交金额和 Phase 1 公共组件无回归。
- Story、测试、完整验证和产品经理 C 级真实页面验收均通过后，才允许进入正式 Review。

```text

└─ 行级操作
```

### 3.1 一级抽屉规则

- 标题固定为“跟进详情”。
- 从右侧打开，宽度固定为 `70vw`。
- 右上角提供关闭入口。
- 不跳转页面，不替换当前列表，不实现全屏路由或居中弹窗。
- 抽屉打开时底层门店客户列表继续存在，原列表筛选、排序、分页和滚动状态不得被重置。
- 抽屉内部内容区独立纵向滚动，不推动底层页面布局。
- 关闭后回到原列表状态。
- 本阶段 Drawer 属于 0011 页面业务实现，不抽成 `AdminDrawer`。

### 5.1 用户信息

结构（第二轮 C 级视觉限定修正，产品经理基于真实系统页面新一轮验收反馈，覆盖第一轮描述）：

1. 顶部独立浅灰操作条（不在姓名/头像行内）：
   - 操作条是操作区，只放操作项，不展示 到店/成交 业务状态标签（最终页面验收确认：状态标签不属该区域操作项，不得根据 isVisited/isDeal 自动添加任何状态标签）。
   - 最终四项、顺序固定：手动变更（蓝色文字）、更多操作（蓝色文字）、添加到店（浅蓝描边按钮；文案为“添加到店”，不是“添加到店记录”）、添加拜访记录（浅蓝描边按钮）
   - 操作入口顺序固定：手动变更 更多操作 [添加到店] [添加拜访记录]
2. 身份区：
   - row1 = 头像 + 客户姓名 + 编辑（姓名旁，真实系统确认存在）+ 客资来源变更记录（蓝色文字入口，紧邻姓名，不再靠右）

3. 左右两栏字段：
   - 左栏：预约门店 / 跟进人 / 进入公海时间
   - 右栏：共享人（值 + 添加）、标签（值 + 编辑 + 变更记录）、注册时间
4. 间距要求（最后一轮 C 级微调）：用户信息采用低密度后台详情信息间距——row1（头像+姓名+编辑+客资来源变更记录）与 row2（客资来源 | 微信号 | 手机号）之间适度纵向距离、身份信息区与下方左右两栏之间明显留白、左右两栏内三行之间同步增加纵向间距；label 与 value 保持稳定对齐。保持字段、左右两栏与业务数据完全不变，只调 spacing，不压成紧凑表格、也不扩大到松散卡片布局。

字段数据直接来自当前列表选中的 CustomerRecord；数据缺失展示 `--`，不得自造未定义的业务字段。

Cycle 1 行为边界：

- “添加到店”“添加拜访记录”“手动变更”“更多操作”“客资来源变更记录”“编辑”、共享人“添加”、标签“编辑/变更记录”仅保留视觉入口，不打开二级抽屉或表单，不实现未定义业务。

### 5.2 跟进概览

四张等宽卡片，顺序固定（第一轮 C 级修正：每张卡片为主值 + 分组详细统计，非简单的“标题 + 主值”）：

1. 剩余体验课次数
   - 主值：剩余体验课次数。
   - 详细：总体验课次数 / 总体验课卡数。
2. 总到店记录数
   - 主值：总到店记录数。
   - 详细：有体验课到店次数 / 未到店次数；分隔线后 上次到店时间 / 首次到店时间。
3. 总拜访次数
   - 主值：总拜访次数。
   - 详细：未拜访时长；分隔线后 上次拜访时间 / 首次拜访时间。
4. 总成交金额（元）
   - 主值：总成交金额（两位小数）。
   - 详细：剩余价值 / 总退款金额；分隔线后 总成交课卡数 / 成交课程类型。

视觉规则：

- 白底、浅边框、小圆角、横向等宽排列、卡片高度较高。
- 卡片右上角展示系统信息图标视觉（不依赖图标库，CSS 绘制）。
- 主值数字明显更大；辅助信息为普通后台文字字号。
- 分组之间使用浅色分隔线；不使用彩色 Dashboard 卡片，不增加趋势、图表或环比信息。

间距要求（第二轮修正）：卡片内部纵向留白增加（内边距与主值/分组间距放宽）；“总拜访次数”卡的“未拜访时长”改为上下层级展示（label 在上、value 在下），不做左右强制紧凑键值；其余字段、Mock 值与四卡结构保持不变。

交互视觉（最后一轮 C 级微调，产品经理真实系统复验）：

- 整卡 hover 支持轻微“浮起/选中”反馈，四张卡统一实现：cursor 体现可交互；hover 时轻微抬升（约 -1px）、极轻微局部放大（scale 约 1.006）、阴影略增强、边框极轻强化；transition 平滑且短（约 160ms）。禁止大幅 scale、明显跳动、彩色发光、蓝色粗边框、强烈动画或 Dashboard 式悬浮卡。
- 每张卡右上角 info 图标保留，接入现有 Ant Tooltip（不新增公共组件）：深色/黑色背景、白色文字、小圆角、小箭头指向图标、出现在图标上方附近、不遮挡主数字；鼠标 hover 与键盘 focus 均可触发。
- 四条 Tooltip 文案为产品经理确认原文，必须逐字一致、不得润色加标点：
  1. 剩余体验课次数 → 显示用户剩余的体验课次数信息
  2. 总到店记录数 → 显示用户的总到店记录数统计
  3. 总拜访次数 → 显示用户的总拜访次数统计
  4. 总成交金额（元） → 显示用户的总成交金额统计
- 整卡真实点击业务结果尚未确认：本 Cycle 只复刻 hover 交互视觉与可交互反馈，不擅自跳转 Tab、不打开 Drawer、不新增路由、不新增业务点击结果；如样式实现需绑定 click 也保持无副作用，后续由产品经理确认点击结果后单独补交互。
