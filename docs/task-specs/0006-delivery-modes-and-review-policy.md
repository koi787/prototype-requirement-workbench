# 0006｜交付模式与高效 Review 规则

## 需求确认卡

- 任务模式：M1 快速改动模式。
- 业务目标：为需求原型工作台建立分级交付、UI 验收和高效 Review 规则，减少低价值返工并保持必要质量门槛。
- 修改范围：`AGENTS.md`、`docs/task-specs/README.md` 和本任务单。
- 明确不做：不修改业务源码、需求 JSON、Storybook、测试、依赖、构建配置或页面视觉。
- 业务规则：四种任务模式、三级 UI 验收、产品验收前置、Review 分类和轮次上限必须长期生效。
- UI 等级：A 级；本任务无页面改动，UI 验收不适用。
- 验收标准：三份文档口径一致、Markdown 结构完整、修改范围准确，并完成提交与推送。

## 背景

项目已经具备任务单、开发、产品验收、Codex Review 和 Git 交付链路。为避免小改动套用重型流程、视觉细节无限扩张或限定复审重新打开需求范围，需要建立统一的任务模式和 Review 边界。

## 目标

1. 由 GPT 在执行前判断任务模式并输出需求确认卡。
2. 按任务风险选择 M1、M2、M3 或 M3-S。
3. 用 A、B、C 三级口径明确 UI 验收深度。
4. 将产品经理真实页面验收置于 Codex 正式 Review 之前。
5. 固定 Review 分类、阻塞定义和复审轮次。
6. 将小闭环最小验证与最终完整验证分开。

## 四种任务模式

### M1 快速改动模式

- 目标当天完成。
- 使用一页任务单。
- 每个小闭环执行相关最小验证，最终交付前执行完整验证。

### M2 标准业务页面模式

- 目标 1—2 个工作日。
- 允许最多两个开发闭环。
- Claude 首版完成并自检后，先由产品经理进行真实页面验收；确认后才进入 Codex 正式 Review。

### M3 基础设施模式

- 单独排期。
- 用于 Schema、通用组件、稳定锚点、页面壳和公共能力。
- 按跨页面影响检查兼容性、类型边界和回归风险。

### M3-S 轻量通用修复

- 用于影响范围较小、问题已经明确定位的通用修复。
- 不使用重型基础设施 Review。
- 不得借修复扩展为架构重写或无关重构。

## UI 验收等级

- A 级：业务结构一致。默认等级。
- B 级：关键视觉风格一致。M2 的关键区域可明确采用。
- C 级：像素级接近。只有产品经理明确要求时采用。

未明确要求 C 级时，轻微字号、间距、颜色、阴影、像素位置和非必要重构建议不得阻塞。

## Review 规则

Review 固定输出：

1. 阻塞问题。
2. 建议优化。
3. 已知债务。

只有功能错误、规则错误、关键交互不可用、明显回归、安全问题、假测试，以及 lint、类型检查、测试或构建失败可以作为阻塞。

每个任务最多一次正式 Review 和一次限定复审。限定复审只检查原阻塞项及明显回归，不得扩张到新的低价值问题。

## 验证节奏

- 每个小闭环只执行与改动直接相关的最小验证。
- 最终交付前执行 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 和 `pnpm build-storybook`。
- M1 同样需要最终完整验证。

## 入口提示规则

后续 Claude 和 Codex 的入口提示只需引用根目录 `AGENTS.md` 和当前任务单，不重复复制完整治理规则。任务特有范围、业务规则和验收标准仍必须写入任务单。

## 不允许修改的范围

- `src/`。
- `.storybook/`。
- `package.json` 和 `pnpm-lock.yaml`。
- 需求 JSON、Schema、页面、Story 和测试。
- 远程仓库配置及历史提交。

## 验收标准

1. `AGENTS.md` 完整包含任务模式、需求确认卡、UI 分级、Review 边界和验证节奏。
2. `docs/task-specs/README.md` 为后续任务单提供一致的模式和 Review 模板规则。
3. 本任务单自包含并明确记录执行范围。
4. Markdown 标题层级和代码块完整。
5. Git 差异只包含允许的三份治理文档。
6. 提交信息为 `docs: 增加分级交付与高效Review规则`，并推送到 `main`。

## 执行与交付

- 执行者：Codex。
- 本任务为治理文档维护，不交给 Claude。
- 完成后报告修改文件、验证结果、提交哈希、推送结果和最终 Git 状态。

## 任务完成通知

本任务完成后按照根目录 `AGENTS.md` 的“任务完成通知”规则执行。Codex 使用用户级 `notify` Hook 自动通知，不手动运行通知命令，不重复通知。
