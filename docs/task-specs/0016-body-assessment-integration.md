# 0016｜硬件检测数据接入——体测仪一期

## 1. 任务确认卡

- **任务模式**：M3｜跨产品业务能力与产品域接入。任务同时新增“移动端｜奥本运动”产品域、SCRM 客户业务域，并建立跨端复用的体测标准数据模型；不按普通单页 M2 拆散为两个需求编号。
- **业务目标**：将 InBody 与 BIACN 体测数据以统一报告能力接入奥本运动移动端，并在 SCRM 客户详情中提供可追溯的体测记录查询和查看入口。
- **修改范围**：移动端用户中心、统一体测报告、体测数据适配层、SCRM 完整客户列表、客户详情基本信息、后续 Cycle D 的“体测美容记录”、对应 Story、测试与最终一条需求实现记录。
- **明确不做**：真实硬件/API/数据库、LocalStorage、真实老后台后端能力、美容检测字段、BIACN 新报告设计、既有业务重构以及任何付费能力。
- **业务规则**：一个需求编号、两个产品消费者、一个标准体测数据模型；统一报告采用“固定模板 + 数据源适配”，设备差异在 adapter 收敛，页面不直接解释供应商 JSON，也不因设备缺值删除或重排字段。
- **UI 等级**：C 级。真实参考截图优先于现有组件，现有产品视觉优先于 Ant Design 默认效果。
- **验收总则**：先完成移动端 Cycle A/B 并由产品经理验收，再完成 SCRM Cycle C/D 并由产品经理验收；之后才进入 Formal Review、限定修复/复审和发布。

## 3. 背景

当前工作台已有 SCRM 产品及其潜客管理、员工业务域，但尚无“移动端｜奥本运动”产品域，也没有面向 SCRM 客户的体测记录能力。真实业务需要将 InBody 与 BIACN 两类设备报告统一呈现在奥本运动移动端，并让 SCRM 客户详情能够查看同一客户的历史体测记录。

0016 是一个跨产品业务需求，不拆为两个编号。跨端复用对象是标准体测数据与设备适配能力，不是把移动端页面塞入 SCRM 壳，也不是强迫两端复用同一视觉组件。

## 4. 业务目标

1. 建立独立的“移动端｜奥本运动”产品工作区与真实用户中心入口。
2. 以当前 InBody 报告为统一视觉与信息架构，让 InBody、BIACN 数据驱动同一套移动端报告组件。
3. 在 SCRM 新增“客户”业务域，完整复刻当前生产客户列表，并通过列表进入真实客户详情上下文。
4. Cycle C 只实现客户详情“基本信息”；Cycle D 再增加“体测美容记录”，支持来源筛选、体测列表、体测详情及美容记录空状态。
5. 通过统一标准数据模型保证移动端报告和 SCRM 记录读取同一口径，避免两套字段解释。

## 10. 统一体测报告数据模型

统一模型至少包含：

- 记录身份：`recordId`、`customerId`、`source: 'INBODY' | 'BIACN'`、`measuredAt`。
- 受测者：身高、体重、性别、生日/年龄；设备记录 ID 与奥本客户 ID 必须分离。
- 报告核心：身体评分、体脂率、骨骼肌、总水分、BMI、去脂体重。
- 身体成分：体脂肪、无机盐、蛋白质、腰臀比、成分分数、SMI。
- 节段数据：固定五区 `rightArm/leftArm/trunk/rightLeg/leftLeg`，每项包含数值、单位和状态。
- 调节建议：体重控制、脂肪控制、肌肉控制、目标体重、建议热量摄入。
- 设备元数据：供应商检测 ID、设备检测 UUID、设备序列号、产品型号及可选原始响应引用。
- 统一模板中的正式字段槽位始终存在；设备能力只决定该槽位的 `value` 是否有值，不决定字段 DOM、所属模块或位置是否存在。概念上应采用 `field: { value: T | null }` 或等价稳定模型，而不是让 BIACN adapter 省略整个字段。
- 页面不得把不同供应商的非同口径字段强行互换。`value = null` 表示当前设备没有已确认的同口径值，不表示该字段已从统一报告模板删除。

标准模型同时供移动端报告、SCRM 列表 selector 和 SCRM 详情使用。组件不得直接读取 BIACN 原始 JSON 路径。

## 11. InBody / BIACN 适配策略

1. 为 INBODY、BIACN 分别建立纯 adapter，将设备输入转换为同一 `BodyAssessmentReport`/ViewModel。
2. 移动端只实现一个统一报告组件；Story 通过不同稳定 mock/adapter 输出驱动同一个 Report UI。
3. 统一报告固定信息架构、模块顺序、字段顺序和字段位置。来源变化只允许改变字段值、单位、状态，以及极少量已有明确语义差异的标题文案。
4. SCRM 使用同一标准记录生成列表摘要与详情内容，但使用 SCRM 自己的视觉组件。
5. 来源差异、单位/状态表达、符号换算和衍生值只在 adapter/入库 mock 层处理；禁止在 JSX 散落 `source === 'BIACN'` 分支或大面积切换不同 DOM。
6. ViewModel 必须提供完整固定字段槽位；设备无同口径值时返回 `value = null`，不得通过缺少字段、section capability 或条件渲染让字段/模块消失。
7. InBody 稳定历史 mock 已由产品经理确认，唯一来源为 `docs/reference/03-inbody-current-report.jpg`；只允许录入截图中明确可读的展示数据，不得从 BIACN 数据反推或补造截图未出现的 InBody 底层原始字段。

数据流冻结为：

```text
InBody 设备数据 ─┐
                 ├─ Adapter → 统一报告 ViewModel → 同一个 Report UI
BIACN 设备数据 ──┘
```

## 17. 体重控制计算规则

- 业务公式：肌肉控制 `1.4` - 脂肪控制 `11.6` = `-10.2kg`。
- 真实系统应在报告入库环节计算并持久化衍生值。
- 原型固定 mock 直接保存 `weightControl = -10.2`，UI 只格式化，不在每次渲染时重复承担业务计算。
- 测试需要分别保护原始正值脂肪控制与最终负号展示，防止双重取反。

## 18. 目标体重计算规则

- 业务公式：当前体重 `75.2` + 肌肉控制 `1.4` - 脂肪控制 `11.6` = `65.0kg`。
- 真实系统在报告入库过程计算和持久化。
- 原型固定 mock 直接保存 `targetWeight = 65.0`，UI 不重复计算。

## 19. 固定模板、空值与不可替换指标

### 19.1 固定字段骨架

统一体测报告以截图 03 为唯一视觉和信息架构基准。InBody 与 BIACN 必须共用以下固定骨架及顺序：

1. 身体评分。
2. 顶部核心四项：体重、体脂率、骨骼肌、总水分。
3. 肌肉含量。
4. 身体成分：体脂肪、无机盐、蛋白质、成分分数、腰臀比、SMI。
5. 脂肪含量。
6. BMI、去脂体重、目标体重、体重控制、脂肪控制、肌肉控制、建议热量摄入。

切换来源时不得重新排版、移动字段、自动补位、改变列数、减少行数、重组模块或造成页面整体高度和字段位置大幅跳动。

### 19.2 缺失字段最终规则

统一模板已有字段不得因为当前设备无同口径值而删除。设备缺值时必须：

- 保留字段名称、原有位置、所属模块、DOM 槽位和页面布局。
- 仅让值区域为空；不显示 `--`、`/`、`N/A`、`暂无`、`0` 或 `0.0`，除非真实 InBody 页面本身对该字段已有不同空值规范；“建议热量摄入”按 19.4 的统一模板规则显示 `—`。
- 不显示近似指标，不自行推导，不让后续字段补位。

单纯“设备没有值”不再是待确认项。只有要永久删除统一模板字段、两种设备确需不同业务模块或字段语义需要产品级重定义时，才重新提请产品经理确认。

### 19.3 SMI 最终规则

- InBody 按稳定 InBody mock 展示真实 SMI。
- BIACN 当前无确认的同口径字段，仍保留 `SMI` 标签和原位置，值区域为空。
- 禁止隐藏或删除 SMI，禁止以 FFMI、`strong_index`、`19.3` 或其他身体指数替代。

### 19.4 建议热量摄入最终规则

- InBody 按稳定 InBody mock 展示真实建议热量摄入。
- `composition.tee.value = 2515` 的业务语义是总能量消耗，不是建议热量摄入。
- 两种来源共用“加油～ / 您高于标准体重 XX.XXkg”提示模板；InBody 使用 `7.80kg`，BIACN 使用统一 ViewModel `weightControl` 绝对值格式化为 `10.20kg`，不读取厂家新字段。
- BIACN 仍保留“建议热量摄入”标签和原位置，无同口径值时显示中文长横线 `—`。
- 禁止隐藏/删除该字段，禁止以 TEE `2515` 替代，禁止改名为“总能量消耗”或额外增加总能量消耗字段。

### 19.5 不新增的 BIACN 指标

即使 JSON 存在，本期也不得新增：身体年龄、基础代谢、总能量消耗、肌肉量、钙质、FFMI/strong_index、体型评估、肥胖评估、腹部肥胖评估、虚弱评估、营养评估、理想体脂率、理想肌肉量、理想骨骼肌、理想脂肪量及其他 BIACN 独有指标。

### 19.6 节段模块的设备差异

节段肌肉和节段脂肪不是“缺值”。两种来源保持相同模块、相同五个部位和相同位置；InBody 沿用真实页面表达，BIACN 展示已确认的 kg 数值，`grade` 仍保留在标准数据模型中但本期报告 UI 不展示状态文案。不得为了表面一致把 BIACN kg 换算成百分比，也不得根据 `prv` 推导比例。

### 19.7 评分区域原型演示辅助交互

- 同一个评分区域继续使用截图 03 的位置、仪表形态、尺寸和版式，不因可点击而增加突兀的“切换设备/报告”控件。
- 评分文案可按已确认语义变化：InBody 使用“InBody评分”和对应分值；BIACN 使用“身体评分 70分”。位置与视觉骨架不变。
- 切换必须更新整份 ViewModel，包括评分、核心四项、节段数据、身体成分、BMI、去脂体重和全部调节建议；不得只改评分数字。
- BIACN 下 SMI 继续保留槽位且值为空；建议热量摄入继续保留槽位并显示 `—`，不得以 TEE `2515` 替代；切回 InBody 后恢复对应真实值。
- 该切换是“原型演示辅助交互”，不是正式生产业务。正式业务打开某次记录时只根据该记录的 `source` 选择数据，用户不能把一条真实记录从 InBody 改成 BIACN。
