# 0007｜需求查看文字样式与 SCRM 名称统一

## 1. 任务信息

- 任务模式：M3-S｜轻量通用修复。
- UI 等级：B 级｜关键视觉风格一致。
- 开发执行：Claude + DeepSeek V4。
- 产品验收：产品经理。
- 独立 Review、验证及经确认的 Git 操作：Codex。
- 当前产品：SCRM。
- 当前模块：潜客管理。
- 当前页面：门店客户。

本任务只修复已明确定位的通用需求标记文字样式问题，并统一现有 SCRM 页面壳和 Storybook 业务目录名称。不得扩展为需求查看系统重写、页面重构或新增业务页面。

## 2. 需求确认卡

### 2.1 业务目标

1. 修复进入“需求查看模式”后，带需求编号的业务字段文字明显缩小的问题。
2. 保证原型体验模式和需求查看模式下，同一业务文字的字号、字重和行高保持一致。
3. 统一 SCRM 页面壳品牌名称和 Storybook 业务目录名称。
4. 让后续新增页面（例如“到店记录”）复用通用需求标记和页面壳时，自动继承正确的文字样式及名称。

### 2.2 修改范围

1. 需求查看模式的通用 `RequirementMarker`、通用样式或文字包裹层。
2. SCRM 页面壳中的左侧品牌名和主体系统标题。
3. Storybook 中 SCRM 业务目录的 title 与目录排序。
4. 与本轮改动直接相关的有效测试和文档记录。
5. 必要的现有公共配置或最小常量；不得扩张为新的品牌配置架构。

### 2.3 明确不做

- 不修改门店客户业务字段。
- 不修改 52 列数量、字段名称和顺序。
- 不修改筛选业务规则。
- 不修改需求 JSON 正文。
- 不修改需求编号 1—12 的稳定映射。
- 不新增“到店记录”页面。
- 不新增列表字段。
- 不新增操作子页面。
- 不重构 `RequirementViewContext`。
- 不重写需求查看系统。
- 不修改 Storybook Addon“需求说明”面板及 Channel 协议。
- 不进行 C 级像素复刻。
- 不顺带处理其他视觉债务。
- 不修改 package name、product ID、Addon ID 或 `src/products/scrm/` 目录名称。
- 不恢复或引入任何公司品牌。

### 2.4 业务规则

1. 需求查看模式只能增加：
   - 蓝色需求编号；
   - 点击能力；
   - Hover、选中和高亮状态；
   - 需求抽屉联动。
2. 需求查看模式不得改变业务文字的：
   - `font-size`；
   - `font-weight`；
   - `line-height`；
   - 原有文本内容；
   - 业务语义。
3. 蓝色需求编号必须作为独立附加元素排列在业务文字旁边，不能通过缩小业务文字腾出空间。
4. 编号点不得遮挡表头文字、排序图标、筛选控件、状态标签、操作菜单文字或模式切换按钮。
5. 模式切换不得造成明显的表头高度、列宽、行高跳动，不得导致业务文字重新排版或表格横向滚动位置丢失。

### 2.5 验收标准摘要

- 两种模式下同一业务文字的字号、字重和行高一致。
- 编号点作为独立元素显示，不压缩或遮挡业务文字和交互入口。
- 左侧导航顶部品牌区显示“SCRM系统”。
- 主体顶部系统标题显示“SCRM管理系统”。
- Storybook 业务目录显示“SCRM”。
- 需求编号、抽屉、排序、筛选、菜单、固定列、横向滚动和页面状态无回归。

开发前必须重新检查当前代码，不得仅根据本任务单猜测实现：

3. 这种“编号点视觉类与业务文字包裹层复用”的方式存在将较小编号字号施加到业务文字的风险，是本轮首要排查点。
4. 表头需求点由 `StoreCustomerList.tsx` 基于 `REQUIREMENT_POINTS` 统一生成，不应逐列增加字号补丁。
5. 当前页面壳可见名称为“示例 SCRM”和“示例 SCRM 管理系统”。
6. 当前 Story title 为 `示例 SCRM/潜客管理/门店客户`，`.storybook/preview.tsx` 排序配置也使用“示例 SCRM”。
7. 门店客户当前保留 8 个 Story，测试基线为 4 个测试文件、251 项测试。

Claude 的交付报告必须给出实际根因；若最终根因与上述风险点不同，应提供可复现证据，但仍须采用通用、限定的修复。

## 5. 实现约束

1. 字号修复优先落在 `src/prototype-core/requirement-view/` 的通用能力中。
2. 编号点视觉样式与业务文字容器样式必须职责分离；业务文字应继承原业务区域的字号、字重和行高。
3. 不允许在每个表头、筛选项、状态标签或菜单项上逐个写字号补丁。
4. 不得使用 DOM 扫描、Ant Design 私有类、DOM 序号、文字匹配或脆弱 CSS 选择器修复字号。
5. 不得用固定高度、隐藏溢出或缩小字体掩盖编号布局问题。
6. SCRM 名称优先通过现有 `src/products/scrm/product.ts`、页面壳或最小稳定常量统一来源。
7. 不要为了两个页面名称新建复杂配置系统；当前只有单一页面壳时允许使用最小常量。
8. Story title 和 `.storybook/preview.tsx` 的排序项必须同步，避免目录名称与排序配置混用。
9. 如同步更新 `PROJECT_STRUCTURE.md` 或 `CHANGELOG.md`，只记录本轮名称和通用样式事实，不扩展其他文档重写。
10. 不得修改 0007 任务单本身，除非产品经理另行确认。
