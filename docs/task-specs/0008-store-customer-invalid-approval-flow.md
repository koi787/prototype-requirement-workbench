# 0008｜门店客户列表调整与无效客资审批流程

## 1. 任务信息

- 任务模式：M2｜标准业务页面。
- 整体页面 UI 等级：A 级｜业务结构一致。
- 审核抽屉、详情抽屉、状态标签和表单校验 UI 等级：B 级｜关键视觉风格一致。
- 不进行 C 级像素复刻。
- 开发执行：Claude + DeepSeek V4。
- 产品验收：产品经理。
- 独立 Review、验证及经确认的 Git 操作：Codex。
- 当前产品：SCRM。
- 当前模块：潜客管理。
- 当前页面：门店客户。
- 建议功能分支：`feature/0008-invalid-approval-flow`。

本任务在现有门店客户页面上完成列表字段调整和无效客资申请、审核、详情闭环。不得复制页面、另建平行版本或新增“到店记录”页面。

## 2. 需求确认卡

### 2.1 业务目标

1. 调整门店客户列表的到店、成交及无效审批相关字段。
2. 将原来直接生效的“标注无效客资”改为申请与审核流程。
3. 支持审核人员查看申请并填写审核结果。
4. 支持申请人与审核人员查看申请详情和审核详情。
5. 保留现有门店客户页面、需求查看能力和主要业务交互。

### 2.2 修改范围

1. 门店客户当前列表字段、字段顺序、类型、模拟数据和展示格式。
2. 无效审批状态标签、筛选名称与对应筛选逻辑。
3. 无效申请抽屉、审核抽屉、只读详情抽屉。
4. 管理员与普通门店账号两种原型身份。
5. 页面本地模拟申请、审核、退回和重新申请状态流转。
6. 操作菜单按状态及身份显示合法入口。
7. 当前页面只读需求说明、页面需求点映射、稳定锚点和 0008 正式需求批次。
8. 与本任务直接相关的 Story、测试、项目结构说明和变更记录。

### 2.3 明确不做

- 不新增“到店记录”菜单、页面或 Story。
- 不接后端接口、数据库或真实业务数据。
- 不做真实附件上传、存储或下载。
- 不建设登录、真实用户或完整 RBAC 权限系统。
- 不展示完整历史审批时间线。
- 不实现批量审核。
- 不实现审批撤回。
- 不实现审核通过后的自动转移、公海回收或其他下游业务。
- 不调整与本任务无关的筛选项或列表视觉。
- 不重构 `RequirementViewContext`。
- 不修改 Storybook Addon 协议。
- 不做 C 级像素复刻。
- 不处理其他技术债务。

### 2.4 UI 验收等级

- 整体列表、字段顺序和操作结构按 A 级验收。
- 审核抽屉、详情抽屉、状态标签、错误提示和表单校验按 B 级验收。
- 轻微间距、阴影、非关键颜色和像素差异不得在 Review 阶段升级为阻塞。

### 2.5 验收标准摘要

- 当前页面最终为 51 列，指定字段删除、移动、新增和更名准确。
- 无效申请提交后只进入“待审核”，不得直接生效。
- 管理员可审核，普通门店账号不可审核。
- 通过、退回、详情和重新申请状态流转准确。
- 需求查看模式只打开需求说明，不执行申请、审核、排序或重新申请。
- 现有筛选、排序、分页、固定列、横向滚动、需求抽屉和页面状态无明显回归。

## 4. 实现原则与状态边界

1. 复用现有 `StoreCustomerList` 页面，不复制 51 列页面或模拟数据。
2. 原型业务状态放在门店客户页面本地状态或页面专用 Hook 中，不进入 `prototype-core`。
3. `RequirementViewContext` 只保留通用需求查看能力，不加入无效审批业务状态。
4. 页面数据可在组件初始化时由 `propData` 或 `rawCustomers` 生成可变的本地原型记录；不得直接修改导入的静态数组。
5. Story 和测试应通过公开 props、页面专用状态参数或现有模拟数据进入指定身份和审批状态。
6. 不得通过 DOM 扫描、Ant Design 私有类名、DOM 序号或复杂选择器驱动状态。
7. 行级操作和锚点统一使用稳定 `record.key`，不得使用当前页行号。
8. 时间、附件和身份均为可重复验收的模拟数据，不接真实系统。
9. 测试需要确定时间时，应使用固定模拟时间或可注入时间来源，避免依赖测试执行时刻。
10. 原型附件只保存安全元数据和本地预览状态，不保存真实文件，不上传服务器。

- 可见名称：`新办成交金额`。
- 建议数据 key：`firstDealAmount`。
- 建议类型：`number | null`；展示层负责格式化，不把 `--` 混入金额值。

位置：

```text

```

展示规则：

- 有值时统一保留两位小数，例如 `29.90`。

## 6. 无效客资申请流程

### 6.1 流程调整

原流程：

```text
标注无效客资
→ 填写备注和附件
→ 提交后直接生效
```

新流程：

```text
标注无效客资
→ 提交无效申请
→ 无效审批状态变为“待审核”
→ 审核人员审核
→ 审核通过或审核退回
```

提交申请后：

- 无效标注不得立即生效。
- 状态只变为“待审核”。
- 生成最新一次申请信息。
- 普通申请人可以查看详情。
- 管理员可以进入审核。
- 状态变更只作用于当前原型内存数据，不发起网络请求。

### 6.2 无效申请抽屉

入口：

- 状态为 `--` 时，操作菜单“标注无效客资”。
- 状态为“审核退回”时，操作菜单“重新申请”。

页面形式：

- 使用右侧抽屉，不创建独立路由。
- 建议标题：首次申请为“提交无效申请”，重新申请为“重新提交无效申请”。
- 标题如需调整必须保持“申请”语义，不得让用户误以为提交后立即生效。

申请信息：

- 申请人。
- 申请时间。
- 申请原因或备注，统一字段标签建议为“申请备注”。
- 申请附件。

申请备注：

- 最多 200 字。
- 产品经理只确认了长度上限，未明确必填；V1 不得擅自增加必填拦截。
- 输入超过上限时必须阻止继续输入或显示明确校验错误。

申请附件：

- 非必填。
- 只实现原型级选择、缩略图、移除和展示。
- 不接真实上传服务器。
- 不保存真实文件。
- 使用安全的模拟附件元数据，不在仓库中加入内部截图。

按钮：

- 提交申请。
- 取消。
- 右上角关闭。

取消或关闭不改变记录状态和最新申请信息。

## 7. 审核无效标注抽屉

### 7.1 进入方式

```text
操作栏
→ 审核无效标注
```

- 使用右侧抽屉。
- 不创建独立路由页面。
- 标题固定为“审核无效标注”。
- 只有管理员面对“待审核”记录时显示该入口。

### 7.2 申请信息区

只读展示：

- 申请人。
- 申请时间。
- 申请备注。
- 申请附件。

### 7.3 审核信息区

字段：

1. 审核意见
   - 必填。
   - 单选。
   - 选项：通过、退回。
2. 备注
   - 最多 200 字。
   - 通过时非必填。
   - 退回时必填。
3. 上传附件
   - 始终非必填。
   - 仅做原型选择、缩略图、移除和展示。

按钮：

- 确认。
- 取消。
- 右上角关闭。

### 7.4 校验和提交保护

- 未选择审核意见时不能确认，并显示明确校验提示。
- 选择“通过”时备注可以为空。
- 选择“退回”时备注不能为空。
- 退回未填写备注时必须显示明确校验提示，并保持抽屉打开。
- 备注不得超过 200 字。
- 附件不影响提交。
- 取消或关闭不改变状态。
- 确认处理期间应禁用重复确认或使用等效状态守卫。
- 连续点击确认不得生成重复审核结果或重复状态变更。
- 审核完成后关闭审核抽屉，列表状态和可用操作立即更新。

## 8. 审批状态流转

### 8.1 状态机

```text
--
└─ 提交无效申请 → 待审核

待审核
├─ 审核通过 → 审核通过
└─ 审核退回 → 审核退回

审核退回
└─ 重新申请 → 待审核
```

禁止流转：

- 提交申请不得直接进入“审核通过”。
- 普通门店账号不得从“待审核”执行审核。
- “审核通过”不得直接重新申请。
- “待审核”不得重复提交第二份申请。
- 取消或关闭抽屉不得触发任何状态变化。

### 8.2 初始状态 `--`

可操作：

- 标注无效客资。

### 8.3 待审核

管理员：

- 审核无效标注。
- 查看详情。

普通门店账号：

- 查看详情。

### 8.4 审核通过

业务含义：

- 无效标注正式生效。
- 该客资在当前原型中按无效客资处理。
- 本轮不实现转移、公海回收或其他下游动作。

可操作：

- 查看详情。

### 8.5 审核退回

业务含义：

- 无效标注不生效。
- 客资保持原有效状态。

可操作：

- 查看详情。
- 重新申请。

### 8.6 重新申请

- 允许修改申请原因。
- 允许修改附件。
- 提交后状态重新变为“待审核”。
- 旧的审核信息不继续作为当前审核结果显示。
- 当前原型至少保留最新一次申请和与该申请对应的审核信息。
- 不展示完整历史审批记录。

### 9.1 入口

以下入口打开只读详情抽屉：

- 点击非空的“无效审批状态”。
- 操作菜单“查看详情”。

标题固定为：

```text
无效标注详情
```

### 9.2 申请信息

- 申请人。
- 申请时间。
- 申请备注。
- 申请附件。

### 9.3 审核信息

待审核时：

- 审核状态：待审核。
- 审核人：`--`。
- 审核时间：`--`。
- 审核备注：`--`。
- 审核附件：`--`。

已审核时：

- 审核结果。
- 审核人。
- 审核时间。
- 审核备注；通过时没有备注可展示 `--`。
- 审核附件；没有附件可展示 `--`。

详情抽屉：

- 只读。
- 不允许直接修改申请或审核结果。
- 关闭后不改变列表状态。
- 当前行状态变化后再次打开，必须展示最新一次申请和审核信息。

## 10. 权限原型规则
